# Relife Web OS — Mobile touch UX contract

The Web/PWA is optimized for fast one-hand clinic use, not gesture novelty.

## Interaction contract

- Tap is the primary interaction for every important workflow.
- Swipe may be added only as a secondary shortcut and must keep a visible fallback action.
- Long-press is optional and never required to complete a workflow.
- Primary touch targets are at least 48px high/wide where practical.
- Critical/recurring actions stay in the lower thumb zone through bottom navigation or large visible action cards.
- A tap must have immediate visual press feedback; network work may continue after that feedback.
- One screen should not depend on competing horizontal gestures.
- Scope/department switching remains explicit via the Combined / Physio / Dental segmented control.

## Owner home contract

The first screen is decision-first:

1. Today snapshot
2. Items needing owner attention
3. Large quick actions
4. Financial summaries

The owner should be able to reach Today Schedule, New Patient, Finance Operations, and Pending Approvals with one visible tap from Home.
